# update20：郁金香打不开，问题出在哪 —— 物理模型 / 物理参数 / 倒奶模型 三方诊断（N = 256）

## 要回答的问题
模拟的郁金香一直打不开花瓣。可能的原因有三个：
1. **物理模型**：表层方程本身缺机制，参数怎么调、入口怎么改都画不出来；
2. **物理参数**：方程没问题，参数没调对；
3. **倒奶模型**：拉花缸算出来的入口（流量、落点、速度）不对。

办法：把这三样分别放开、分别固定，用视频反传（精确伴随梯度 + Adam），看哪种组合能把郁金香打开。
**先不管参数是否物理**——参数放在很宽的范围里随便调。

## 四个试验（都只用 tulip + leaf 训练，同一个起点）
起点：`closures/bp256_trained.json`（update18 在 N=256 反传得到的参数；没有这个文件时用新基线 v05n）。

| 代号 | 参数 | 入口（倒奶） | 回答什么 |
|---|---|---|---|
| D `both_wide` | 放开（宽范围） | 放开，范围是测量误差的 2.5–3 倍 | 表层模型**到底能不能**画出郁金香 |
| C `both` | 放开（宽范围） | 放开，只在测量误差内 | 在真实可能的入口下能不能画出来 |
| A `params` | 放开（宽范围） | 按测量值（倒奶模型 + 深度落点） | 只靠调参数行不行 |
| B `inlet` | 固定在起点 | 放开，只在测量误差内 | **孤立拉花缸**：只修正倒奶行不行 |

- **参数**（9 个，不管是否物理）：cp 0.1–6、β 0.02–30、ν 1e-4–0.05、κ_Q 0.2–15、κ_c 0–3、κ_t 0–2、κ_r 0.001–1、B_dep 30–30000、p_dep 0.5–12。
- **入口修正**：每杯每 0.2 s 一个节点（放宽时 0.3 s），节点之间线性插值，平滑变化。每个节点 6 个量：
  - 落点平移 dx、dy：误差内 ±8 mm（拉花缸位姿误差 5–10 mm），放宽 ±20 mm；
  - 流量倍率：误差内 ×0.5–2（倾角差 1° 流量差 30–50 %），放宽 ×0.2–5；
  - 落到液面的竖直速度倍率：误差内 ×0.71–1.4，放宽 ×0.4–2.5；
  - 水平到达速度增量：误差内 ±0.10 m/s，放宽 ±0.30 m/s。
  
  奶流开/关的时刻不改（视频里看得到）。落点椭圆大小、液柱直径按修正后的流量和速度重新算，规则和到达记录一样。
- **损失**：和以前的反传完全一样（每一帧视频都比，多尺度，温度从 0.10 退火到 0.03）。每次迭代都保留视频 IoU 最高的那一组。

## 事先定好的判据
跑完对每个试验算两样，和标定用同一把尺：
- **J**：0.25 × IoU + 0.75 × 结构分，按视频自身 0.25 s 的一致性归一（1 = 和视频自己一样好）。现在 tulip 是 0.64–0.72。
- **花瓣分离率**：视频里互相分开的白色部件（≥ 20 mm²），在模拟里也分开的比例；取最后 30 % 的观测帧。视频自己 = 1。

**“打开郁金香”= tulip J ≥ 0.80 且 分离率 ≥ 0.50。** 然后：

| 结果 | 结论 |
|---|---|
| D 和 C 都打不开 | **1 物理模型的问题** |
| A 打开（C 也打开） | **2 物理参数的问题**，倒奶模型在误差内够用 |
| A 打不开，B 打开（C 也打开） | **3 倒奶模型的问题**，参数没问题 |
| A、B 都打不开，C 打开 | **2 + 3**：两样都要改 |
| 只有 D 打开 | **1 为主**：要把入口改到超出测量误差才行——看 D 的入口改动图，像不像真实的手 |

`results_diag/summary.md` 会自动套这个判据并写出结论；同时请你看图，判据只是辅助。

## 时间
- 总预算 `BUDGET_H=8` 小时。四个试验平分（每个约 1.7 小时，约 60–70 次迭代；N=256 每次迭代约 90 秒，两杯并行），每个试验结束后留 0.3 小时出图、出视频。
- 显存 ≥ 45 GB 时两个试验同时跑（`PAR=2`），否则一个一个跑。24 GB 的卡一次只跑一个（tulip 的逐帧存档约 8 GB）。
- 顺序是 D → C → A → B：最能判断“模型行不行”的先跑。
- 中断后再执行同一条命令：跑完的试验跳过，没跑完的从断点（`state.npz`）接着跑。

## 须知
- **这是诊断，不是标定。** 入口修正是用视频反推的，违反了“手的动作是测量值、不能用图案去改”的原则，所以它只用来判断问题出在哪，**不会**拿去当模型的一部分。
- 参数放开后可能跑到很不物理的值，这正是这次要看的：如果连不物理的参数都打不开，就是模型的问题。
- 只用 tulip 和 leaf；留出三杯只在 A 里用冻结参数跑一遍，只报告。
- 放开入口时，落点的移动速度会变快。日志里每次迭代的 `scan` 是“每帧落点移动 / 求解器自己的步长上限”，测量入口约 1；超过 3 说明落点跳得太快、白色可能沉积成断续的点，请告诉我。
