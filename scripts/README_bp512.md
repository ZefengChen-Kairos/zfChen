# update18：新基线反传训练（256 → 512）+ 512×512 拉花视频

## 做什么
- 从新基线出发：V0.5 在保缝逐帧目标上用 CMA-ES 标定的结果，文件是 `latte_imex/data/closures/v05n_AB_cmaes_N48.json`。
- 用可微求解器的精确伴随梯度做反传，Adam 优化 8 个闭合参数。只用 tulip 和 leaf 训练。
- 分两段跑：
  1. N=256：先把参数调到位。两杯在两个进程里并行。
  2. N=512：从第 1 段的最好结果接着细调。两杯依次跑，因为 tulip 的逐帧存档约 16 GB。
- 训练完，用最好的参数跑五杯（tulip、leaf 两杯标定，heart、push_heart、swan 三杯留出），得到：
  - 每杯的目标分 J：把 512 的结果守恒地合并到 48×48，和 CMA 标定用同一把尺子，可以直接和新基线比。
  - `<杯>_sim512.mp4`：512×512 模拟拉花视频，一格一个像素。
  - `<杯>_compare.mp4`：四联对比视频，依次是真实视频、视频白度目标、反传训练 N=512、新基线 N=48。
- 有剩余时间时，再算未训练的新基线在 N=512 上的 J。这样可以把"分辨率带来的变化"和"训练带来的变化"分开。
- **总时长控制在 8 小时内。** 每段的时间从命令开始时起算，到点就停，保留目前最好的参数，再接着出视频。

## 运行
上传 `bp512_update18.tar.gz` 到 `/root/autodl-tmp/`，然后：

```bash
mkdir -p /root/autodl-tmp/u18 && tar xzf /root/autodl-tmp/bp512_update18.tar.gz -C /root/autodl-tmp/u18 \
  && cd /root/autodl-tmp/u18 && bash scripts/autodl_bp512.sh
```

- 命令会在后台运行并立即返回。看进度：`tail -f /root/autodl-tmp/u18/results/bp512.log`
- 每次迭代都会打印一行：迭代号、损失、vIoU、每杯正向和反传各用几秒。从第一行就能看出 256 和 512 每次迭代要多久。
- 跑完把 `/root/autodl-tmp/u18/results_bp512.tar.gz` 发回给我，五杯视频和 J 表都在里面。

## 可调参数（加在命令前面）
| 变量 | 默认 | 作用 |
|---|---|---|
| `BUDGET_H` | 8 | 总时长上限（小时） |
| `ITERS256` / `ITERS512` | 80 / 40 | 每段最多迭代次数；时间先到就提前停 |
| `LR256` / `LR512` | 0.03 / 0.015 | Adam 步长（单位盒） |
| `N1` / `N2` | 256 / 512 | 两段的网格。例如只想 256 的话：`N2=256 ITERS512=0` |
| `INIT` | v05n 闭合 | 起点 |
| `FG=1` | | 前台运行 |
| `FORCE=1` | | 自检不通过也继续（不建议） |

例如只给 6 小时：`BUDGET_H=6 bash scripts/autodl_bp512.sh`

## 中断后重跑
直接再执行同一条命令。已完成的阶段会跳过；没跑完的训练段从它自己的最好参数接着跑。

时间预算会从这次重启重新算，最多 `BUDGET_H` 小时。如果想沿用第一次的起始时间，加上 `KEEP_T0=1`。

同一个目录里同时只能有一个运行；如果第二次启动，它会提示 `ABORT` 并退出。

## 先自检（可选，CPU 上几分钟）
```bash
SMOKE=1 bash scripts/autodl_bp512.sh
```
这会在 CPU 上把整条流程走一遍：N=32 → 48，只模拟第 1 秒，只做 tulip 的视频。结果放在 `results_smoke/`。

正式运行开头也会自动做两个 GPU 自检：
1. Warp 和 numpy 两个求解器结果一致（N=64，200 帧）。
2. 一步反传能正常跑通。

任何一个不过就停下，请把 `results/selftest_*.txt` 发给我。

如果第 2 段（N=512）报显存不足（out of memory），用同一条命令加上 `N2=384` 重跑即可；第 1 段已完成，会自动跳过。

## 须知
- **耗时是估计。** 4090 上 N=256 每次迭代约 1.5–2 分钟（两杯并行），N=512 每次约 15–25 分钟。实际以日志里每次迭代打印的秒数为准。
- **训练目标和选参标准不同。** 反传优化的是可微的视频损失（软 IoU 类，和以前 GPU 反传用的一样）；训练中保留的"最好"是视频 IoU 最高的那一次。最后用标定目标 J 评价：`summary.txt` 里新基线 N=48、新基线 N=512、训练后 N=512 三列并排，看 J 到底有没有提高。
- **新基线的物理结构没变**：没有能生成细棕线的机制。512 的画面会更清楚，数值扩散也小很多；但层的 V 形、最后图案合成一块的问题大概率还在。这次主要回答的是"分辨率够高时，线能不能保住"。
- **只用 tulip 和 leaf 训练。** heart、push_heart、swan 只在最后用冻结参数评价。
