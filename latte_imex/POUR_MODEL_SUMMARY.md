# 倾倒模型现状总结（2026-10-09）

一句话：**意图 → 虚拟咖啡师 → 壶（液面 / 堰流 / 射流 / 账本）→ 量纲耦合 → 二维表层求解器（IMEX）→ 杯面图案。**
壶这一段没有三维流体，是几个代数式加两个常微分方程，每帧微秒级；图案全部由二维表层模型输运出来。
详细推导在 `PITCHER_MODEL.md`（第 0–13 节），二维模型在 Notion Z1 页第 3–4 节。本文只说"现在是什么、值是多少、哪些验证过、哪些没有"。

## 1. 链条各环节

| 环节 | 输入 → 输出 | 做法 | 参数（当前值） | 状态 |

| 壶杯碰撞 | 姿态 → 需要抬高多少 | 杯作障碍（r_in 40、r_out 43 mm、高 7 cm、沿高 1 cm、向壶倾 20°）；壶外壁 1440 点，二分求最小竖直抬高 | 余量 2 mm | 几何上可靠 |
| 虚拟咖啡师 | 意图（落点路径、壶嘴高度、想要的流量、抖动）→ 姿态 | 固定 1/120 s 时钟。瞄准：壶嘴 = 目标落点 − 上一帧射流水平偏移（0.3 s 低通）。手腕：**前馈** tilt_for_flow(Q_want)（当前装奶量下的堰流律反解，0.1 s 内到位）+ PI 微调（0.4°/s 每 mL/s，积分 0.45），限 60°/s；奶没到壶沿时按 60°/s 甩；停倒只回到奶离开壶沿，之后 4°/s 慢回（停在起流水头下方一两度）。壶嘴高度按 0.25 m/s 限速跟随意图。抖动幅度 0.25 s 淡入淡出 | 预倾 40°，看到的流量 0.25 s 低通 | 10-09 修了两个 bug：零流量移位后重启太慢（细切没奶）、高度瞬跳踢起晃荡（细切开头 30 mL/s 喷涌） |

| p_dep | 2 | 1.56 | 1.3–2.3 | — | 2 |

重要事实：Codex 的入口是按量纲缩过的（底座实际流量 0.1–0.2 mL/s、足迹 0.6 mm、速度 0.06–0.14 m/s，比真实小 10–100 倍），它猜的是四个无量纲组 U⊥²/(B d)、κ_Q Q、κ_r V_R、κ_t|v∥| 的工作点。按真实入口反算这四个组得到的闭合参数，和联合扫描靠末帧评分自己找到的一致。所以 B_dep = 240 只在 Codex 的缩小入口下成立，换物理入口必须换 B_dep，这不是模型表达力问题。

## 3. 验证过什么，没验证什么

已验证（可复跑）：
- `test_pitcher`：容量、V 形堰解析式、体积账本 1e-19、抛体、反解倾角、到达时延 30–200 ms。
- 二维求解器：静止条纹、守恒 1e-14、与 Codex 768 HLLC 六图同输入对照 IoU 0.80–0.98。
- 六个图案结构：修过咖啡师、用 #9 闭合和量纲耦合后，六个 V0.5 翻译动作（一个数没改）全部成形（`results/joint_sweep/codexmap/six_phys9_128.png`）。
- 郁金香 256² 与 512²：条纹更锐，褐缝宽度不变（中位 2–2.5 mm）。

没验证（全部是猜的或扫出来的）：
- 壶：C_d、h_k、h_on、τ、ζ、出口方向。要用"水 + 色素 + 秤 + 尺"的自拍实验定，不需要会拉花。
- 咖啡师：增益、限速、预倾都是手设的"合理人手"，没有和视频里的壶运动对过。
- 闭合参数：九个数没有一个是从视频反演出来的。扫描只说明哪些重要（B_dep、kQ、β），不说明值是真的。
- c_p：末帧完全不敏感，必须用过程帧。

## 4. 网格的教训（学长 V0.5 后续测试 + Codex + 本页）

学长那一节（"底座三网格：平均差下降，细纹尚未收敛"，384/768/1536）的要点：
1. **平均差在降，细纹没收敛。** 守恒限制到共同 384 网格后相邻内域浓度平均 L1 0.0192 → 0.0145；但固定剖面 y = 0.10 上阈值 0.4 的暗缝数是 0 / 3 / 21 条，而且都窄于事前定的可分辨宽度 4/384 杯径（0.8 mm）。结论是"更窄的缝保留原值并标 unresolved"，不宣称收敛。
2. **比网格要先守恒映射 h、m、q 再算 c、u**，不能直接相减不同原生采样点；相邻差包含阶梯壁、入口采样、自适应步序的变化，不是误差界。
3. **窄入口求积在粗网格失败**：n = 128、r = 0.008 杯径、q = 4 的核 L1 误差 0.023 超门槛，q = 8/16 才降到 0.0056/0.0013；768 上同类误差 0.0008。
4. **细切 ROI 的时间步不收敛**：整杯平均差随步长减小而降，但细切区域的相邻差反而从 3.5e-4 升到 4.6e-4，最大差 0.038 → 0.069。
5. **不许用 D 或渲染锐化去补/抹细纹**；细纹指标（条数、宽度、阈值）要事前登记，只数宽于可分辨宽度的。

对本页的直接启发：
- 我们 96² 扫描的一格是 0.83 mm，比学长的可分辨宽度还粗。所以 96² 只能排序，不能评细纹；这和我们看到的"96 → 256 叠瓣和弧纹才出现、256 → 512 条纹更锐但褐缝不变宽"一致。
- 评价褐缝要定一个宽度门槛（建议 ≥ 1.5 mm，即 256² 上 5 格），低于门槛的条纹只记数不计分。我在 `gap_diagnosis.py` 里用的是 ≥ 1 mm。
- 入口足迹 r1 ≈ 1–3 mm = 256² 上 3–10 格，核求积是够的；96² 上细切足迹 0.5 mm 只有 0.6 格，这是 96² 的另一个失真来源。
- 细切阶段是时间步最敏感的地方（学长的 ROI 结果），我们现在细切用物理足迹 1 mm 圆，比 Codex 的 0.3 mm 宽三倍，敏感性会小一些，但没有单独测过。

## 5. 什么参数能出褐缝细纹

把两轮扫描 160 组的 96² 末态按五条纵切线数褐缝（阈值 0.5，≥ 1 mm），和参数做相关（`results/joint_sweep/gap_metrics.json`，`gap_rich_samples.png`）：

| 指标 | 相关最强的参数（符号 = 参数增大时指标的变化） |
|---|---|
| 郁金香褐缝条数 | β −0.39，抖壶方向横向 −0.32，κ_t +0.27，B_dep −0.21，抖幅 +0.19，p_dep −0.18，kQ −0.16 |
| 郁金香褐缝总长 | β −0.39，κ_t +0.28，横向 −0.28，抖幅 +0.24，B_dep −0.20 |
| 心形褐缝条数 | β −0.51，κ_t +0.18 |
| 白区内部对比度（条纹明暗） | B_dep +0.64，κ_t −0.21，抖幅 −0.21 |

读法：
- **阻尼 β 小**是最一致的因素：推开的旧奶要能走得远，褐色才留得下来。β 1.2–1.8 的样本有 12–16 条缝（#3、#10、#77、#31），β 3 以上的多数只有两三条。
- **横向、幅度大一些的抖壶**（6–8 mm）比前后抖出更多缝；前后抖让流量脉动但把缝抹掉。
- **B_dep 偏低（1200–1600）、κ_t 偏高**：χ 低一点意味着更多奶走牵引而不是沉积，推而不盖。但 B_dep 太低白区会淡，白区对比度（+0.64）要 B_dep 大。两者相反，所以 B_dep 有一个中间最优（1500–3000）。
- ν、c_p、κ_r、p_dep 对缝几乎没影响（|r| < 0.15）。

但这些都是**细条纹**（1–3 mm），不是真实郁金香瓣与瓣之间 4–9 mm 的空带。专门做过的对照（`gap_diagnosis.py`，256²）：足迹缩到 0.3 倍、加 85% 锁相脉动、加密到 512²，褐缝宽度都不变。宽带要"先推开、后变白"的时延闭合（PITCHER_MODEL.md 第 13 节末）；参数扫不出来。

## 6. 已知差距与下一步（按收益排）

1. **评分换掉**：末帧面积损失连茎都扣分。改用过程帧 + 形状特征（瓣数、褐缝条数与宽度、羽纹数、颈曲率），褐缝宽度门槛事前定。
2. **c_p 从扫描里拿出来**，按物理固定 2–4，用心形前 4 s 白盘扩张速度核；这样 IMEX 才真正划算。
3. **时延闭合**：已实现并试过五轮（PITCHER_MODEL.md 第 14 节）。只加时延没用；水下奶堆进入压力项先推、τ_d 后浮出才出宽褐带（推推乐 3 → 7 mm）；储量要部分随流（α ≈ 0.3），否则心形的细切被推空或宽带又被填回。工作点 τ_d 0.2 s、w 0.5、α 0.3，待从视频量 τ_d。
4. **壶参数自拍标定**：C_d、h_k、h_on、τ、ζ，水 + 色素 + 秤。
5. **动作重优化**：物理固定后只扫动作，四个图案各几十组；等第 1 项做完再做，否则会优化成大白块。
6. 低流量贴壁淌、奶泡分层、杯体回正（ALE）仍未管。
