# 和真实视频比：V0.5 原版 vs 全物理（strictB3）

> 对象：六个图案的**末帧**。比较三张图：(1) V0.5 原版（Codex 入口，256²，`runs/v05_256`）；(2) 全物理 strictB3：入口量全部在物理范围内，逐笔壶嘴高度是重新猜的（P2 反设计）；此外流量脉动的相位也改了，**两种相位都是事后对动作的再猜**：郁金香、树叶、天鹅把 5 Hz 流量峰从 Codex 的 π（摆到两端）挪到 0（过中线），这是 P4f 的修补，是看到 P4 用 π 失败之后才改的（`v05allphys/results.md` 第 6 节 (1)）；千层心用 strictfp90，把峰挪到 π/2（回摆途中），是看过 π 和 0 都不成形之后才改的；大白心、推推乐没有脉动。另附 P1（c_p 仍是 Codex 的 0.3）作中间参照；(3) 真实视频末帧（`latte_imex/targets/<p>.npz` 的白度 w 和原始相机帧）。
> Codex 的控制是猜的，不是咖啡师的真实动作，所以只能比最后的图案，不能比时序。
> 单位：D = 8 cm 杯径，D³ = 512 mL，s；边界距离给 D，括号里是 mm。没有改 `latte_imex`，也没有发布任何东西。
> 代码：`compare.py`（指标、对齐）、`structnum.py`（结构计数）、`figs.py`（图）、`tables.py`、`assemble.py`、`rectcheck.py`（校正核验）。

## 结论

**全物理和 V0.5 离真实视频一样远。** 两者 IoU 之差在 −0.04 到 +0.11 之间，六个图案平均 +0.01；而两者与真实之间的 IoU 只有 0.29–0.74。真实图案普遍更大，细褐线多 2–6 倍，元件布局也不同（推推乐有一颗独立的小心，郁金香是叠起来的几颗心）。把入口物理化，既没有让图更接近真实，也没有让它更远，所以这些差距不是入口物理化造成的。它们来自猜的动作还是模型本身（单层闭合、0.67–3.2 mm 的足迹、扩散都限制褐线的宽度和密度，也影响白区大小），这次比较分不开：它固定了动作、只换了入口。要用 `latte_imex/stage_scripts` 里从视频读出的真实动作去跑（任务 #30）才能分开。

## 0. 怎么比的

**数据与坐标。** 求解器场 c_M[iy, ix] 按 `frame_check.json` 的约定，用 c_M[::-1, :] 放进目标的 T 系。真实照片的校正 RGB 有两条路：`frames.npz` 的 `ell[-1]` + `video_extract.rectify`，或者 `targets.liquid_ellipse` + `targets.warp`。两者得到的 RGB 完全相同（相关 1.0）。用它重算的白度与 `targets/<p>.npz` 的 w 差 ≤ 3e-8，所以图里的照片和计算用的 w 是同一帧、同一几何。

**方向核验。** 把 T 数组按"第 0 行在上"显示，再映射回相机图像，这个映射的 Jacobian 行列式在六个图案上都 > 0（0.81–1.94）。也就是说，显示出来的是相机俯视图的一个**旋转**，没有镜像，是物理俯视图。核验天鹅和推推乐时（`compare_real_orientation.png`）发现，有两个目标**不在**模拟所用的规范坐标里（规范坐标：B 侧、起倒点在上，出口、尾巴在下）。仓库自己的 stage 脚本里写明了这一点：
- **树叶**：`stage_scripts/leaf.json` 写明 B 侧（心形叶尖）在 −y_M，"与其他五个图案的约定差 180°"，应按 c_M[:, ::-1] 比。
- **天鹅**：`stage_scripts/swan.json` 写明目标 rot = 0，"没有转到规范方向"，B→D 轴在 M 系 +45°（规范是 −90°）。

所以先对这两个目标做一次**固定的坐标修正**（不是拟合）：树叶转 180°（逐格精确），天鹅转 135°（双线性插值，真实白区 0.217 → 0.213）。修正后肉眼核对：真实天鹅头在左上、颈沿左侧下行、翅在右，与 V0.5 天鹅布局一致，不需要镜像；真实树叶的心形叶尖在上、宽底座在下，也与 V0.5 一致。下面所有数字都在修正后的规范坐标里算。未修正的数字留在 json 的 `uncorrected` 里（树叶 V0.5 原样 IoU 0.435、天鹅 0.337）。推推乐按 stage 脚本 B→D 轴偏规范约 39°，但仓库的 target rot 本来就是按规范手调的，这里没有动，所以表里推推乐的数字是在目标偏 stage 脚本轴约 39° 的方向上算的；按同一来源修正 39° 的敏感性检查见第 4 节，IoU 变化 ≤ 0.02，结论不变。

**指标**（所有模拟用同一个算子，都在目标网格上算；目标网格 192²，树叶 256²）：
- **IoU**：模拟白（c > 0.4，另给 c > 0.5）对真实白（w > 0.5），只算杯内（R = 0.49 D）。
- **边界距离**：对称平均边界距离 [D]，两张白掩膜各自边界到对方边界的平均欧氏距离，再取两者的平均。边界指杯内有非白 4-邻居的白格。
- **白区**：白格数 / 杯内格数。
- **褐缝**：直接用 `v05audit/cf_runner.py` 的 `axis_gaps`。沿 x = 0 和 x = ±0.05 D 三条线每 0.1 mm 采样；短于 0.5 mm 的白段去掉；夹在两段白之间、≥ 1 mm 的褐段算一条缝。模拟阈值 0.4，真实阈值 0.5。
- **辅助结构计数**（`structnum.py`）：白连通块（≥ 4 mm²）；x = 0、±0.05、±0.10 D 五条线上的褐线数（缝 + 凹谷，凹谷要求突起 ≥ 0.1、半高宽 ≥ 0.5 mm）；心形的凹口深度（轴上从瓣顶到第一段白）。

**两种对齐，分开报，不混用：**
- **原样（raw）**：模拟按算出来的样子，不做任何变换。
- **最佳刚体（best）**：把模拟绕杯心转 |θ| ≤ 25°（物理俯视图里逆时针为正），再平移 |dx|, |dy| ≤ 0.06 D，取 IoU(c > 0.4) 最大的一组。先按 1° / 0.01 D 的网格搜，再在附近按 0.25° / 0.0025 D 细化。这一组变换同样用于 IoU(c > 0.5)、边界距离和褐缝。

**一个必须先说的限制：IoU 对方向和结构几乎不敏感。** 我额外做了一个诊断，不属于上面两种对齐：在 ±180° 全圆、每 5° 一档、带平移搜最佳 IoU。结果全圆最优与 ±25° 窗内最优相差 ≤ 0.02。例如 V0.5 大白心在窗内是 0.663，转 155° 反而是 0.668。所以这里的 IoU 主要量的是"白团的大小和位置重不重合"，判结构还得靠看图和条纹计数。

## 2. 逐个图案：哪里像，哪里不像

图：`compare_real.png`（整杯）、`compare_real_zoom.png`（中央 ±0.36 D 放大，含 P1）、`compare_real_overlay.png`（白掩膜叠加：黑 = 两者都白，红 = 只有模拟白，蓝 = 只有真实白）。

### 2.1 大白心

**真实**：一颗实心大白心，占杯面 0.367。顶部凹口深而窄（沿轴 11.8 mm），底部尖拉成一根细尾通到杯边（瓣顶到尾端 57 mm）。心内部均匀白，末帧里看不到中缝。

- **像**：三个模拟都是心形，有凹口和尖，左右两瓣、尖的位置都对。
- **V0.5 不像的地方**：心小一圈（0.254，瓣顶到尖 45 mm，真实 57 mm），凹口只有 4.0 mm，尾巴短。内部实白，这一点和真实一致。
- **全物理不像的地方**：心大一点（0.273），所以 IoU 高（原样 0.675 对 0.564，最佳 0.736 对 0.663），边界距离也近（4.2 对 5.6 mm）。但它的凹口往下连成一条灰褐中缝，沿轴 c < 0.4 共 19.4 mm（P1 是 16.9 mm），旁边还有几道灰纹。**真实的心没有这条缝**。凹口深度上，两者离真实一样远：V0.5 浅 7.8 mm，全物理深 7.6 mm。
- **判**：按指标，全物理更近；按样子，V0.5 更像，因为真实的心是实白的。

### 2.2 推推乐

**真实**：三块分开的白，分别是 B 侧（左上）一颗独立的小心（约 230 mm²）、中间一颗内心（约 490 mm²）、只在右侧和下侧包住的外弧（约 480 mm²）。块间褐缝 2–4 mm（轴上 4.2 mm）。图案轴比竖直斜约 40°，按 stage 脚本的 B→D 轴约 39°。

- **像**：两种模拟里，臂都是被褐缝隔开的嵌套弧，白区也几乎一样（0.258、0.240，真实 0.251）。
- **不像**：两种模拟都是左右对称的三层：一颗内心，外加每侧两道 V 形臂，所有臂在尖处连成一块（V0.5 是 1 个连通块，全物理 2 个）。没有那颗独立的小心，外弧也不是单侧包的。全物理的缝更清楚、更多（三线 2/4 对 0/2，宽 1.4–2.4 mm），比 V0.5 更像真实那种"分得开"的感觉，但布局同样不对。
- **判**：持平。原样 IoU 0.463 对 0.445，边界距离都是 2.8 mm。和真实的差别不是入口物理化造成的。Codex 的动作是对称三推，本来就没有单独点一颗小心，所以布局差别很可能来自动作；但这次比较分不开动作和模型本身（见结论）。

### 2.3 千层心

**真实**：一颗大心，白区 0.389。两瓣上半部各有约 8–10 道 1–2 mm 的细褐弧，跟瓣的轮廓平行，从中轴一直铺到瓣边。下半部实白。凹口 9.1 mm，尖带细尾。

- **像**：心形、凹口、尖、中轴细线都在。凹口深度上 V0.5 最接近（10.8 mm；全物理 16.8 mm）。
- **V0.5 不像的地方**：心只有真实一半大（白区 0.182）；内部是灰（c 0.6–0.8），在 c > 0.5 的掩膜里一部分算成褐。"层"只有凹口旁一对亮卷加 1–2 道淡弧，铺不到瓣上。
- **全物理（strictfp90，含事后的动作再猜）不像的地方**：大小同样只有一半（0.169），内部更灰，所以 c > 0.5 的 IoU 掉到 0.268（V0.5 是 0.381）。但每瓣有 3–4 道清楚的嵌套亮弧，在 x = ±0.05、±0.10 D 线上数到 3–5 道（V0.5 是 0–4 道）。"一层一层"这一点比 V0.5 更像真实，只是弧集中在中轴两侧，没有铺满瓣。
- **判**：按指标，V0.5 略近（IoU 0.398 对 0.361，最佳 0.466 对 0.430）；按样子，全物理的内弧更像。两者共同差的是大小（面积只有一半）和弧的数量（3–4 道对 8–10 道）。

### 2.4 郁金香

**真实**：在规范坐标里整体斜约 17°（按 stage 脚本的 B→D 轴）。一颗顶心，下面一颗大心，再外面一道带细波纹的底弧（波纹在左侧最明显）。层与层之间是宽褐缝，轴上 19.7 mm 和 5.9 mm，三线合计 7 道。白块分成 7 块。

- **像**：两种模拟都是"顶心 + 嵌套瓣 + 层间褐缝"，缝数接近：V0.5 是 1/5，全物理 2/6，真实 2/7。
- **不像**：模拟的瓣是窄 V 形、左右对称，在尖处连成一块（V0.5 2 块，全物理 3 块）；缝窄，1.8–6.8 mm 对真实 5–20 mm；底弧里没有波纹。全物理的顶心裂成两根细条，底座也变成两根细条（`verify_images.md` 已经写过）。V0.5 的顶心是一整颗。
- **判**：持平。原样 IoU 0.298 对 0.291；边界距离全物理近 0.3 mm。最佳对齐都要转 10–20°，平移顶到边界，说明真实的郁金香更大，而且偏离杯心。

### 2.5 树叶（坐标修正 180°）

**真实**：心形叶尖在上，约 12 对白色 V 形叶片，每片宽 2.5–4 mm，片与片之间是 1–2 mm 的褐线。中脉把叶子分成两半（两大块白）。底部是一道宽底座。叶长约 0.7 D。五条竖线上一共数到 66 道褐线。

- **像**：叶尖小心、中脉、两侧叶脉，两种模拟都有，整体布局也对（修正后叶尖都在上）。
- **V0.5 不像的地方**：叶只有约 0.35 D 长，坐在一个灰色的圆底上；叶脉每侧 6–7 道（五线合计 28 道），约为真实的一半。不过叶脉是"褐底上的白片"，和真实的观感一致。
- **全物理不像的地方**：叶脉更淡，是灰底上的浅灰条（五线合计 24 道）；底座变成两根细条。白区 0.274，比 V0.5 的 0.250 更接近真实的 0.339，所以 IoU 稍高（0.464 对 0.431）。
- **判**：按指标，全物理略近；按样子，V0.5 的叶脉更像。两者都只有真实一半的叶片数，叶也短得多。

### 2.6 天鹅（坐标修正 135°）

**真实**：左上是一颗带凹口的心形头，S 形颈沿左侧下行，右侧到上方是一大片翅膀，约 10 道 V 形羽，羽间褐线 1–2 mm，外围还有几道宽弧。**没有单独的圆形身体**。白区 0.213，分成 7 块；五条竖线上数到 74 道褐线。

- **像**：修正后，两种模拟的布局与真实一致：头在左上，颈沿左侧，翅在右。颈、头、翅三样都有。
- **V0.5 不像的地方**：头是一根朝左的直喙，真实的头是心形团。翅只有 5–6 根羽（五线合计 12 道褐线），面积约为真实的一半。下面多出一个灰色圆底身体，叠加图里那一大片红色就是它，真实没有。
- **全物理不像的地方**：头卷成一个钩，比直喙圆一些，但仍不是心形团；翅同样只有 5–6 根羽（13 道）；身体也多出来，上面还有一道褐月牙。
- **判**：持平。原样 IoU 0.348 对 0.319，最佳 0.408 对 0.402；边界距离全物理近 0.2–0.6 mm。

## 3. 全物理比 V0.5 离真实更近还是更远

**不近也不远。** 两者的差别（IoU 除大白心 +0.11 外都在 ±0.04 以内；原样边界距离差 0–1.4 mm，六个图案全物理都不更远）比两者共同离真实的差距（1 − IoU 为 0.32–0.71，边界距离 2.5–7.2 mm）小得多：多数图案小一个量级，大白心也小 3–4 倍。这里没有做噪声估计（没有重复运行，也没有 128² 对 256² 的对照），所以不说这个差别是不是噪声。逐项看：

|---|---|---|
| IoU c>0.4，六图平均 | **+0.009**（大白心 +0.11、树叶 +0.03；其余四个 −0.04…−0.01） | **+0.006** |
| IoU c>0.5，六图平均 | −0.018（全物理内部更灰；千层心 −0.11） | −0.028 |
| 边界距离，六图平均 | −0.0049 D（−0.4 mm）；六个都不比 V0.5 远，其中推推乐只差 5e-6 D，等于持平 | −0.0030 D（−0.2 mm）；4/6 更近 |

**两者共同离真实远在三个地方**，而且都比两者之间的差大一个量级：
1. **大小**：千层心、树叶、大白心的真实白区是 0.34–0.39，模拟只有 0.17–0.27；千层心只有真实的一半。

3. **元件布局**：推推乐的独立小心和单侧外弧，郁金香叠起来的几颗心和带波纹的底弧，天鹅没有单独的身体。这些在 Codex 猜的动作里根本没有，换不换物理入口都出不来。

这三条都不是入口物理化造成的：换不换物理入口，它们都在。第 3 条（布局）里的元件在 Codex 的动作里根本没有，最可能是动作的问题，即在哪里倒、倒多少、摆几下。前两条（大小、细褐线的数量）既可能来自动作，也可能来自模型本身：单层闭合、0.67–3.2 mm 的足迹（V0.5 是 0.10–1.76 mm）和扩散都限制褐线能有多细、多密，也影响白区大小。这次比较固定了动作、只换入口，分不开这两者。所以真要贴近视频，下一步是按视频里的动作去倒（`latte_imex/stage_scripts/*.json` 已经有从视频读出的动作，任务 #30）：用真实动作跑，如果差距还在，问题主要在模型；如果差距明显缩小，问题主要在动作。再在入口物理上做文章，帮不了这件事。

## 4. 局限

- **IoU 判不了结构和方向**（第 0 节的全圆诊断）。表里 IoU 的差别，比如 0.03，不能当成"更像"的证据；结构判断以看图和条纹计数为准。
- **最佳对齐的平移经常顶到 0.06 D**（大白心、千层心、郁金香、树叶），所以 best 那一列是"窗口内最好"，不是"任意刚体变换下最好"。全圆诊断给的最大值也只高 ≤ 0.02。
- **推推乐没做坐标修正**：stage 脚本的 B→D 轴偏规范约 39°，超出 ±25° 的窗口，所以表里推推乐的数字（原样和最佳）都是在目标偏 39° 的方向上算的。树叶、天鹅用的是同一来源，推推乐没用，处理不一致，所以补了一个敏感性检查（`push_sens.py`，结果在 `push_sens.json` 和 `compare_real.json` 的 `orientation_check.push_heart_sensitivity`）：按 stage 脚本的地标点 B→D 轴在 M 系 −50.6°，修正 PHI = +39.4°，其余算子不变。原样 IoU（c > 0.4）V0.5 / P1 / 全物理 = 0.459 / 0.467 / 0.442（表里 0.463 / 0.448 / 0.445），最佳 0.511 / 0.505 / 0.479（表里 0.507 / 0.503 / 0.488）；原样边界距离 0.0364 / 0.0363 / 0.0376 D（2.9 / 2.9 / 3.0 mm；表里 2.8 / 2.9 / 2.8 mm）。全物理减 V0.5：原样 −0.018（表里 −0.018），最佳 −0.032（表里 −0.019）。IoU 变化 ≤ 0.02，"持平"的判断不变；这和 IoU 对角度是平的一致（未修正时，V0.5 全圆最优 0.506 @ +55°，窗内 0.507）。
- **天鹅的 135°**来自教练叠加点（±0.1 D，约 ±15°），所以再用 ±25° 的窗口去细调。三种模拟的最佳 θ 都在 +9° 到 +13°，即真实的 B→D 轴约在 M 系 +55°（叠加点给的是 +45°）。
- **真实白度 w 会糊掉细线**：1–2 mm 的褐线在 w 里是灰的（0.3–0.5）。千层心左瓣的弧在 w 里几乎没有对比（五线计数里左侧两条线是 0）。所以真实的线数是下限，真实与模拟的差距只会更大。
- **水印**：千层心、郁金香右上方的水印字（"捉你…"）在 w 里算成少量白，面积只有几 mm²。
- **流量相位是事后对动作的再猜**：全物理组的郁金香、树叶、天鹅把 5 Hz 流量峰从 Codex 的 π（摆到两端）挪到 0（过中线）。这是 P4f 的修补，是 P4 用 π 失败之后才改的（`v05allphys/results.md` 第 6 节 (1)：物理入口下"峰在两端"会在中轴扫出褐色空洞）。千层心（strictfp90）把峰挪到 π/2（回摆途中），是看过 π 和 0 都不成形之后才改的。两种相位都在物理范围内，但都不是先验设定，也不是视频里的动作；严格说，全物理组除了逐笔高度，还在这四个图案上重猜了流量相位。
